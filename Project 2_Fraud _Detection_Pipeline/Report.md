 Fraud Detection Pipeline ## Data Science Project 2 — DecodeLabs **Submitted by:** Muqaddas Mukhtar **Program:** BS Bioinformatics **University:** University of Agriculture, Faisalabad --- ## 1. Introduction Fraud detection is an important application of data science and machine learning. E-commerce platforms generate large amounts of transaction data, and machine learning models can be used to identify transactions that may have suspicious characteristics. This project presents a complete fraud detection pipeline using an e-commerce transaction dataset. The workflow includes data loading, preprocessing, feature engineering, fraud-target generation, class balancing, model training, evaluation, and model comparison. --- ## 2. Project Objective The main objectives of this project were: - To explore an e-commerce transaction dataset. - To preprocess numerical and categorical features. - To generate a fraud-related target variable. - To handle class imbalance using SMOTE. - To train Logistic Regression and Random Forest models. - To evaluate model performance using Precision, Recall, F1-Score, and ROC-AUC. - To compare the performance of both classification models. - To identify the better-performing model. --- ## 3. Dataset Description The dataset contains **1,200 e-commerce transaction records**. It includes numerical, categorical, and date-related information. Important attributes include: - Quantity - TotalPrice - PaymentMethod - Transaction Date The dataset was inspected for data types, missing values, and identifier-like columns before model training. Date information was further processed by extracting: - Year - Month - Day - Day of Week --- ## 4. Fraud Label Generation The original dataset did not contain a verified fraud-label column. Therefore, a synthetic target variable named `IsFraud` was created using transaction-based rules. A transaction was labelled as fraudulent if it satisfied one or more of the following conditions: 1. `TotalPrice` was greater than the 95th percentile of TotalPrice. 2. `Quantity` was greater than the 95th percentile of Quantity. 3. `PaymentMethod` was Cash on Delivery. After generating the target variable, the dataset contained: | Class | Records | |---|---:| | Non-Fraud | 1,140 | | Fraud | 60 | | Total | 1,200 | This resulted in a strongly imbalanced classification problem. --- ## 5. Data Preprocessing Data preprocessing was performed before model training. ### Numerical Features Numerical features were processed using: - Missing-value imputation - Standard scaling ### Categorical Features Categorical features were processed using: - Missing-value imputation - One-hot encoding The data was divided into training and testing sets using an **80:20 stratified split**. Stratification was used to preserve the class distribution between the training and testing datasets. --- ## 6. Handling Class Imbalance Because the fraud class represented only a small portion of the dataset, class imbalance could negatively affect model learning. To address this issue, **SMOTE (Synthetic Minority Over-sampling Technique)** was applied to the training data. SMOTE creates synthetic examples of the minority class instead of simply duplicating existing fraud records. This helped provide the machine learning models with more representative fraud examples during training. --- ## 7. Machine Learning Models ### 7.1 Logistic Regression Logistic Regression was used as a baseline classification algorithm. The model estimates the probability that an observation belongs to one of two classes: - Fraud - Non-Fraud It provides a simple and interpretable baseline for comparison. ### 7.2 Random Forest Random Forest is an ensemble learning algorithm that combines multiple decision trees. It was selected because it can capture non-linear relationships in transaction data and can provide feature-importance information. The Random Forest model was compared with Logistic Regression to determine which algorithm performed better. --- ## 8. Evaluation Metrics The models were evaluated using several classification metrics. ### Accuracy Accuracy represents the proportion of correctly classified transactions. ### Precision Precision measures the proportion of transactions predicted as fraud that were actually classified as fraud. ### Recall Recall measures the proportion of actual fraudulent transactions that were successfully identified. ### F1-Score F1-Score is the harmonic mean of Precision and Recall. It is particularly useful when dealing with imbalanced classification problems. ### ROC-AUC ROC-AUC measures how effectively the model separates fraud transactions from non-fraud transactions across different classification thresholds. --- ## 9. Results and Model Comparison The final performance of the two models was: | Model | Accuracy | Precision | Recall | F1-Score | ROC-AUC | |---|---:|---:|---:|---:|---:| | Logistic Regression | 99.17% | 91.67% | 91.67% | 91.67% | 99.71% | | Random Forest | **99.58%** | **100.00%** | 91.67% | **95.65%** | **100.00%** | Random Forest achieved better overall performance than Logistic Regression. It produced the highest: - Accuracy - Precision - F1-Score - ROC-AUC Both models achieved the same Recall of 91.67%. --- ## 10. Confusion Matrix A confusion matrix was used to examine correct and incorrect predictions made by the Random Forest model. The confusion matrix provides information about: - True Positives - True Negatives - False Positives - False Negatives The Random Forest model achieved a Precision of 100%, indicating that the transactions predicted as fraud were correctly labelled according to the synthetic target rules. --- ## 11. ROC Curve ROC curves were used to compare the classification performance of both models. The Random Forest model achieved an ROC-AUC of **1.00**, while Logistic Regression achieved approximately **0.997**. This indicates that both models were highly effective at separating the two classes in the test data, with Random Forest performing slightly better. --- ## 12. Feature Importance Feature importance was extracted from the Random Forest model to identify the transaction features that contributed most to its predictions. Feature importance can help explain which characteristics of the transactions were most influential in the model's decision-making process. --- ## 13. Discussion Both machine learning models achieved very high performance on the test dataset. Random Forest was selected as the best-performing model because it achieved: - 99.58% Accuracy - 100.00% Precision - 91.67% Recall - 95.65% F1-Score - 1.00 ROC-AUC The use of SMOTE helped address the imbalance between fraud and non-fraud classes. The use of preprocessing pipelines also ensured that the required transformations were applied consistently during model development. --- ## 14. Limitations The major limitation of this project is the synthetic nature of the fraud labels. The original dataset did not contain verified fraud outcomes. Instead, fraud labels were generated using rules based on: - TotalPrice - Quantity - PaymentMethod These same transaction features were then used in the machine learning pipeline. Therefore, the extremely high model performance may partly reflect the rules used to generate the target variable. The results should therefore be considered a demonstration of the machine learning pipeline rather than evidence of real-world fraud detection performance. A real-world fraud detection system would require verified historical fraud labels and validation using completely unseen production transactions. --- ## 15. Conclusion This project successfully implemented a complete machine learning-based fraud detection pipeline for e-commerce transaction data. The workflow included: 1. Dataset exploration 2. Data preprocessing 3. Feature engineering 4. Synthetic fraud-target generation 5. Class balancing using SMOTE 6. Logistic Regression training 7. Random Forest training 8. Model evaluation 9. Model comparison 10. Feature importance analysis Random Forest was the best-performing model, achieving **99.58% accuracy, 95.65% F1-Score, and 1.00 ROC-AUC** on the test dataset. However, because the fraud labels were synthetically generated, these results should not be interpreted as real-world fraud detection performance. Overall, the project demonstrates practical knowledge of supervised learning, classification, imbalanced-data handling, Scikit-learn pipelines, and machine learning model evaluation. --- ## 16.
